修复顺序及边界：

1. **Phase 1：协议与后台活动。** 仅处理真实 Responses 终态/status=0，保留失败与取消顺序；保活停止完成后按现有活动重算，无新重试或状态机。完成聚焦回归后独立 reviewer 检查。
2. **Phase 2：资料与发现。** PDF 准确记录提取截断事实并保持旧字符串调用兼容；来源披露只显示对应来源；修正首次可见加载；复用现有保存中状态阻止提前离页；原文打开失败改为准确提示，不增加自动复制兜底。完成聚焦回归与 ArkTS 构建后独立 reviewer 检查。
3. **Phase 3：阅读与导出。** 图候选约束收口到实际写入；模板 style 不消费可见章节；现有 Markdown parser 支持上述两种真实 URL，不替换框架。完成回归、类型检查与构建后独立 reviewer 检查。
4. **集成交付。** 只对本次 diff 做一次有限可维护性检查；完整 Node 测试、类型检查、SDK 构建、受影响模拟器 UI 验证，报告未验证的真机/Provider/系统调度边界。

不纳入修复的主要候选：

- supervisor 内部超时被 abort 抢先拒绝：直接替身 Promise 可复现，但真实 AI adapter、HTTP abort listener 与生产 collectRun 异步链复核得到 outcome=timeout、两次调用及 OVERVIEW=FAILED，判为当前生产路径假阳性，不改。
- 模板文章不要求经典四段 READY：独立模板成功保留 sectionStates={}，失败初稿清除 templateArticle，旧稿失败保留已读正文，符合当前设计。
- PDF 导出隐藏图片：现有合同及 iOS 同策略，属于设计。
- 未调用 RDB 更新方法丢新字段、未调用 purge 删除过期文章：当前无生产调用，不按可达缺陷处理。
- 固定 WantAgent requestCode 导致点击串文章：OpenHarmony Want 相等判定包含 parameters，不能套用 Android PendingIntent 语义。
- 模板预览拦截 data: 会导致空白：主 agent 已在 API 24 模拟器通过真实新建模板草稿→预览验证，示例标题、导语、章节均正常显示。早期立即截图尚未加载完成，等待渲染后的截图排除空白结论；没有保存测试模板。

验证入口修复（单独于功能缺陷）：领域模块 `tsc -p harmony/deepread/tsconfig.json` 基线报自身包名无法解析，Chat tsconfig 的同一依赖图通过。Phase 2 补充该现有配置的自身路径映射，使独立检查可重复运行。
